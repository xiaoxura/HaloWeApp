# HaloWeApp 下一阶段开发计划（v0.2.0）

> 文档状态：可执行草案  
> 编制日期：2026-08-01  
> 基线版本：v0.1.0（`e722f25`）  
> 建议周期：10 人日开发与测试 + 2 人日缓冲；按 1 名小程序开发者估算约 2～3 周

## 1. 阶段定位

v0.2.0 定位为 **可发布的只读 MVP / Release Candidate**。本阶段不继续横向扩充菜单，
而是先保证用户可以稳定完成以下主链路：

1. 打开小程序并浏览文章列表；
2. 搜索目标文章；
3. 正确阅读含图片、代码块、表格等内容的文章；
4. 进入分类或标签列表继续浏览；
5. 点赞、分享，并在异常网络下获得明确反馈。

评论提交属于 UGC 能力，依赖配套 Halo 插件、微信内容安全校验和审核策略，不纳入本阶段
发布范围。评论读取可保留，但默认关闭，且不得阻塞文章阅读主链路。

## 2. 当前基线与问题盘点

### 2.1 已有能力

- 首页文章分页、置顶排序、Banner 和文章卡片；
- 文章详情页面框架、阅读量上报、点赞和分享；
- 分类、标签及其文章列表；
- 评论列表展示及本地/远程开关；
- 站点统计和基础设计规范；
- `wx.request` 请求层及 Halo Public API 封装。

### 2.2 已确认的问题

以下问题来自当前代码检查以及对 `config.baseUrl` 所指测试环境的接口抽样。Halo 小版本、
主题和插件组合可能产生不同响应，因此实现时应以兼容适配和固定测试样本为准。

| 编号 | 现状 | 影响 | 优先级 |
| --- | --- | --- | --- |
| B-01 | 详情页读取 `res.content.html`，抽样接口实际返回 `content.content` 和 `content.raw` | 正文可能为空，阅读主链路中断 | P0 |
| B-02 | 作者头像等资源可能是 `/upload/...` 相对地址，当前未补齐站点域名 | 图片加载失败 | P0 |
| B-03 | 远程配置接口只判断 HTTP 200；插件不存在时可能收到登录页 HTML 并被缓存 | 配置状态不可预测，缓存被污染 | P0 |
| B-04 | 首页搜索入口仍为提示占位；现有搜索接口返回结构与文章列表不同 | 用户无法检索内容 | P1 |
| B-05 | 首页与分类文章列表分别维护相同的文章转换逻辑 | 字段修复容易遗漏，维护成本高 | P1 |
| B-06 | 站点统计接口不一定返回标签数；当前“标签”可能长期显示为 0 | 数据展示不准确 | P1 |
| B-07 | 空数据和请求失败多数共用同一界面，部分页面缺少重试入口 | 弱网体验差、问题难定位 | P1 |
| B-08 | “我的”页面包含多个仅弹出“开发中”的菜单 | 发布版本存在明显死入口 | P1 |
| B-09 | 点赞状态只存在于当前页面实例，重新进入后可重复操作 | 交互反馈不一致 | P2 |

## 3. 阶段目标与成功标准

### 3.1 产品目标

- **O1 正文可读**：兼容 Halo 2.x 常见详情响应，正文、图片和作者资源可以正确显示；
- **O2 搜索闭环**：用户可从首页进入搜索页，完成搜索、查看结果并进入详情；
- **O3 异常可恢复**：断网、超时、空数据、接口不兼容均有明确状态和重试方式；
- **O4 无插件可运行**：未安装配套插件时使用安全默认值，不请求或缓存无效配置；
- **O5 具备发布门槛**：核心转换逻辑有自动化测试，关键机型完成真机回归。

### 3.2 可量化成功标准

- P0 验收用例通过率 100%，P1 用例通过率不低于 95%；
- 首页、搜索、分类列表、文章详情主链路无未捕获异常和永久 loading；
- 至少覆盖 10 篇不同结构的真实文章，其中应包含无封面、相对资源、长文、代码块、
  表格和多图文章；
- 搜索覆盖普通中文、英文、特殊字符、空关键词、无结果和网络失败；
- 配套插件缺失、超时、返回 HTML、返回非法 JSON 时均保持 `commentEnabled: false`；
- 小程序主包不超过微信当前主包限制，新增依赖后记录构建前后包体积；
- 开发者工具与至少 1 台 iOS、1 台 Android 真机完成冒烟测试。

## 4. 本阶段范围

### 4.1 P0：发布阻断项

#### A. 统一数据适配层

新增纯函数适配层，页面不再直接依赖 Halo 原始响应字段：

```text
utils/adapters/post.js       文章列表、文章详情转换
utils/adapters/search.js     搜索命中结果转换
utils/asset.js               相对资源 URL 补全
utils/html.js                正文选择、必要的清理与兼容处理
```

主要规则：

- 正文按明确兼容顺序读取，至少覆盖 `content.raw`、`content.content`、`content.html`；
- `cover`、`avatar`、正文图片等 `/...` 地址使用 `baseUrl` 补全；
- `data:`、`wxfile:` 和已经是 `http(s)` 的地址不重复处理；
- 缺失 `metadata`、`spec`、`stats` 时使用安全默认值，不能使页面崩溃；
- 首页和分类/标签文章列表共用同一个 `normalizePostSummary`；
- 导航参数统一使用 `encodeURIComponent`，加载页统一做参数合法性检查。

#### B. 正文渲染升级

使用 `mp-html` 替换详情页原生 `rich-text`，推荐通过小程序 npm 引入，并提交
`package.json`、锁文件和构建说明。若 npm 构建导致包体或兼容问题，再回退为 vendored 组件，
但不得同时维护两份来源。

首批支持范围：

- 标题、段落、粗体、斜体、链接、引用、列表和分割线；
- 图片自适应、懒加载、点击预览；
- `pre > code` 代码块横向滚动和复制；
- 表格横向滚动，避免撑破页面；
- 对 Halo/主题生成的 `shiki-code` 等自定义标签提供降级规则；
- 忽略 `script`、`iframe`、事件属性和文章内全局 `<style>`，避免污染页面或引入风险；
- 外链无法直接打开时提供复制链接或明确提示。

实现前先从真实博客保存最少 10 份脱敏详情响应作为测试夹具，避免只针对单篇文章调试。

#### C. 远程配置安全兜底

当前配套插件名称和 API group 尚未稳定，因此 v0.2.0 采用“显式启用”策略：

```js
remoteConfig: {
  enabled: false,
  pluginName: '',
  endpoint: '',
  cacheTtl: 21600000
}
```

- 未配置 `pluginName`/`endpoint` 时不发起网络请求；
- 启用后先调用插件可用性检测接口，再拉取配置；
- 仅接受 JSON 对象，并对白名单字段逐项校验；
- 非 2xx、HTML、空响应、字段类型错误均不得写入缓存；
- 缓存带 `fetchedAt` 和 schema 版本，过期配置只可作为短时降级；
- 默认且最终兜底始终为 `commentEnabled: false`；
- 页面通过统一的配置就绪事件或 Promise 获取结果，避免启动时序竞争。

#### D. 主链路修复

- 修复详情正文和相对头像显示；
- 避免重复上报同一次页面会话的阅读量；
- 请求失败后必须结束 loading，并提供重试；
- 刷新与触底加载互斥，避免重复页和重复文章；
- 文章不存在、参数缺失和接口 404 使用独立错误态；
- 评论开关关闭时不请求评论接口，也不渲染评论入口。

### 4.2 P1：体验闭环

#### A. 搜索页

新增 `pages/search/` 并在 `app.json` 注册，首页搜索胶囊跳转到真实页面。

功能范围：

- 输入、清空、提交搜索和键盘 search 事件；
- 最近搜索记录，使用本地存储，支持逐条使用和一键清除；
- 搜索中、结果、无结果、失败与重试状态；
- 结果展示标题、摘要、更新时间，点击后以 `metadataName` 进入详情；
- 搜索 API 的 `<B>...</B>` 命中标记只允许转换为受控高亮节点，禁止直接渲染任意 HTML；
- 空白关键词不请求接口，连续提交同一关键词不产生并发重复请求；
- 当前 API 已确认使用 `limit` 而非标准分页，本阶段默认最多返回 20 条并显示总命中数，
  不实现伪分页。后续确认 Halo 版本支持 offset/page 后再扩展。

#### B. 页面状态统一

提供统一的加载、空数据、错误和重试表现，可先抽取轻量组件，也可在本阶段保持页面级实现，
但文案、图标和交互必须一致。

- 首次加载显示 loading/skeleton；
- 请求失败显示错误态和“重新加载”；
- 成功但无数据才显示空状态；
- 分页失败保留已有列表，不把整页切换为空状态；
- 下拉刷新失败应保留旧数据并结束刷新动画。

#### C. 统计和“我的”页面收口

- 文章、分类、阅读数据继续使用 stats 接口；
- 标签数从标签列表分页响应的 `total` 获取，失败时显示 `--` 而不是伪造 0；
- v0.2.0 未实现的归档、友链、关于和设置入口隐藏或明确置灰，不保留可点击死入口；
- 版本号从单一配置源读取，禁止在 WXML 中硬编码 `v0.1.0`。

### 4.3 P2：有余量再做

- 点赞状态按文章名本地持久化，并定义缓存清理策略；
- 图片加载失败占位图；
- 搜索历史数量上限和 LRU 清理；
- 首屏 skeleton 动画与较细的加载性能优化；
- 为请求增加可控重试，仅限 GET 且最多一次，不自动重试写请求。

## 6. 技术方案与约束

### 6.1 推荐目录调整

```text
├── components/
│   └── page-state/                 # 可选：统一页面状态
├── pages/
│   └── search/                     # 搜索页四件套
├── utils/
│   ├── adapters/
│   │   ├── post.js
│   │   └── search.js
│   ├── api.js
│   ├── asset.js
│   ├── html.js
│   ├── request.js
│   └── runtime-config.js
├── tests/
│   ├── fixtures/                   # 脱敏 API 样本
│   └── *.test.js
├── package.json
└── package-lock.json               # 或实际选用包管理器对应的唯一锁文件
```

### 6.2 API 适配约定

| 场景 | API | 页面只消费的内部模型 |
| --- | --- | --- |
| 文章列表 | `GET .../posts` | `PostSummary` |
| 分类/标签文章 | `GET .../{categories\|tags}/{name}/posts` | `PostSummary[]` |
| 文章详情 | `GET .../posts/{name}` | `PostDetail` |
| 搜索 | `POST .../indices/-/search` | `SearchResult` |
| 统计 | `GET .../stats/-` + 标签列表 `total` | `SiteStats` |
| 运行时配置 | 插件检测 + 自研插件 config | `RuntimeConfig` |

页面层不得再用多级表达式猜测 Halo 字段；兼容逻辑集中在 adapter，并由响应夹具测试。

### 6.3 请求层约定

- 错误对象至少包含 `type`、`statusCode`、`path` 和可展示消息；
- 区分网络错误、超时、HTTP 错误、响应格式错误；
- 日志不得输出评论邮箱、令牌或完整敏感请求体；
- GET query 继续使用 repeat 数组序列化，并补充布尔值、0、中文和特殊字符测试；
- 写操作不自动重试；阅读量和点赞失败不得影响正文展示；
- 页面卸载后不再执行无意义的 `setData`。

### 6.4 内容与资源安全

- 博客正文虽由站长发布，仍不得执行脚本或事件属性；
- 搜索高亮仅识别服务端约定的 `<B>` 标签，其余内容按纯文本处理；
- 所有外部图片域名应加入小程序合法域名清单；
- 文档列出 `request`、`downloadFile`、图片/CDN 域名配置步骤；
- 仓库中禁止提交 AppSecret、PAT 和用户隐私数据。

## 8. 里程碑

### M1：数据链路稳定（第 1～3 天）

- 完成接口样本、内部模型、adapter 和 URL 归一化；
- 修复正文为空、相对资源失败和重复数据转换；
- 完成远程配置安全兜底。

退出条件：使用 fixtures 的 P0 单测全部通过，插件缺失不会污染缓存。

### M2：阅读体验完成（第 4～5 天）

- 完成 mp-html 集成；
- 代码块、表格、多图、链接和长文通过开发者工具验证；
- 详情错误态、阅读量和评论开关行为正确。

退出条件：10 篇文章内容回归通过，无空白正文或横向撑破页面。

### M3：搜索与页面收口（第 6～8 天）

- 搜索主流程和历史记录完成；
- 页面状态统一；
- 站点统计和“我的”页面死入口完成收口。

退出条件：首页到搜索详情、分类到详情两条链路可连续完成。

### M4：发布候选（第 9～10 天）

- 自动化测试、弱网测试、真机测试和包体检查完成；
- README、配置说明、变更日志和版本号更新；
- 生成 v0.2.0 RC，进入 2 人日缓冲期修复缺陷。

退出条件：满足第 10 节发布门禁，无未关闭 P0/P1 缺陷。

## 9. 验收清单

### 9.1 首页与列表

- [ ] 首次加载、下拉刷新和触底分页均不会重复文章；
- [ ] 有/无封面、有/无摘要、有/无分类的文章卡片均正常；
- [ ] 网络失败保留已有数据，并可手动重试；
- [ ] 分类名、标签名和文章名包含中文或特殊字符时仍可正常跳转；
- [ ] 快速连续触底只产生一个下一页请求。

### 9.2 文章详情

- [ ] `content.raw`、`content.content`、`content.html` 三类夹具均能选择到正文；
- [ ] 相对头像、相对正文图片和绝对 CDN 图片均可显示；
- [ ] 标题、列表、引用、代码块、表格、图片和链接布局正确；
- [ ] 图片可预览，代码可复制，超宽内容不撑破页面；
- [ ] 非法 name、404、超时和空正文显示明确状态；
- [ ] 阅读量/点赞接口失败不影响正文阅读；
- [ ] 评论关闭时评论接口请求数为 0。

### 9.3 搜索

- [ ] 空关键词不发请求；
- [ ] 中文、英文、空格和特殊字符可搜索；
- [ ] 高亮标记不会显示为原始 `<B>`，也不会注入其他 HTML；
- [ ] 点击结果能使用 `metadataName` 打开正确文章；
- [ ] 无结果、接口失败、重复提交和超过 20 条结果行为符合设计；
- [ ] 最近搜索可复用、清空，并限制最大条数。

### 9.4 运行时配置

- [ ] 默认配置不开启评论；
- [ ] 插件未配置时不发送远程配置请求；
- [ ] 插件不可用、超时、返回 HTML 或非法字段时不覆盖默认值；
- [ ] 合法配置可缓存，过期缓存会刷新；
- [ ] 清空缓存后冷启动行为一致。

## 10. 发布门禁（Definition of Done）

v0.2.0 只有同时满足以下条件才可标记完成：

1. 所有 P0 任务完成，P0 缺陷为 0；
2. P1 缺陷无阻断主链路的问题，其余均有记录和后续版本；
3. adapter、URL、query 序列化、配置校验和搜索高亮具备自动化测试；
4. 第 9 节验收清单通过并留存测试结果；
5. README、快速开始、合法域名、npm 构建和版本变更说明已更新；
6. 未实现功能不提供可点击死入口；
7. `commentEnabled` 默认关闭，远程插件异常时仍保持关闭；
8. 发布提交打 `v0.2.0` 标签，并保留上一可用版本的回滚路径。

## 11. 风险与应对

| 风险 | 可能性/影响 | 应对 |
| --- | --- | --- |
| Halo 版本或主题导致正文结构差异 | 高/高 | 固化多份真实响应；adapter 集中兼容；正文保留降级链 |
| `mp-html` 不支持主题自定义标签 | 中/高 | 对 `shiki-code` 等预处理为标准 HTML；先做样本验证再全面替换 |
| npm 构建增大包体或配置复杂 | 中/中 | 记录体积基线；必要时改 vendored，但只保留一种依赖来源 |
| 图片位于未登记 CDN 域名 | 高/中 | 扫描测试文章资源域名，形成部署清单并在真机启用校验测试 |
| 搜索结果含服务端 HTML 标记 | 高/中 | 只解析白名单 `<B>`，其余全部转义或按纯文本处理 |
| 配套插件接口尚未定稿 | 高/高 | 本阶段默认禁用远程拉取；插件名和 endpoint 显式配置 |
| UGC 审核与内容安全 | 高/高 | v0.2.0 不提交评论；后续由服务端持有凭据并执行安全检查 |
| 单人开发回归不足 | 中/中 | adapter 自动化测试 + 固定真机矩阵 + 2 人日缓冲 |

## 12. v0.3.0 进入条件

完成 v0.2.0 后，只有以下前置项明确，才启动评论和插件阶段：

- 配套插件仓库、插件名称、API group 和版本策略确定；
- 远程配置 JSON Schema 定稿，含 `schemaVersion`、`commentEnabled`、`minVersion`；
- 微信 `msgSecCheck` 的服务端调用方案确定，AppSecret 不进入小程序；
- 评论频控、重复提交、审核中状态、删除与举报策略确定；
- 用户昵称、头像、邮箱等信息的收集目的、存储方式和隐私说明完成；
- 至少有一个 Halo 2.x 测试站完成插件安装、升级和卸载验证。

建议 v0.3.0 再依次实现：配套插件配置下发 → 内容安全代理 → 评论提交 → 评论回复 →
归档/友链等增强页面，避免再次把多个高风险能力并行铺开。
